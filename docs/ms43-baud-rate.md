# Смена скорости MS43

## Поведение библиотеки и CLI

Порт открывается на 9600 бод, 8E1. После успешной идентификации `Session::change_baud_rate(BaudRate)` согласует скорость с ЭБУ; сам метод идентификации скорость не меняет. `Session::restore_default_baud_rate()` возвращает 9600 той же процедурой. Повторный выбор уже согласованной скорости не отправляет команду смены скорости.

```sh
cargo run -p dmelab-cli -- -v identify --port /dev/cu.usbserial-FT1234 --baud-rate 125000
```

Команда `identify` сначала идентифицирует MS43 на 9600. Если выбрана повышенная скорость, переключается, повторяет идентификацию на ней, затем пытается вернуть 9600 как после успеха, так и после ошибки. Результат выводится после успешного восстановления; ошибка восстановления приводит к ненулевому коду завершения. Для `identify` по умолчанию используется 9600.

Команды [чтения и записи прошивки](ms43-flash.md) используют 125000 по умолчанию и обязательно согласуют повышенную скорость после начальной идентификации и предварительных проверок. Для них 9600 отклоняется; библиотечные `read_flash`/`write_flash` сами управляют разгоном и возвратом скорости.

Повторная идентификация на повышенной скорости — наша проверка канала. В исходном MS4x Flasher переключение выполняется перед чтением или записью, а возврат — при завершении операции.

## Последовательность переключения

1. Очистить буферы и настроить таймаут транзакции.
2. На текущей скорости отправить пакет с адресом `12` и payload из таблицы.
3. Принять и проверить echo, адрес, длину, XOR и статус ответа.
4. При `A0` подождать 200 мс в вызывающем потоке.
5. Изменить скорость UART через транспорт, сохранив остальные настройки линии.

| UART, бод | Payload запроса |
| ---: | --- |
| 9600 | `91 00 25 80 00` |
| 19200 | `91 00 4B 00 00` |
| 38400 | `91 00 96 00 00` |
| 50000 | `91 00 C3 50 00` |
| 107000 | `91 01 86 A0 00` |
| 125000 | `91 01 E8 48 00` |

Payload содержит `91`, трёхбайтовое значение скорости и завершающий `00`. Режим 107000 буквально сохраняет исходное расхождение: значение в запросе ЭБУ равно 100000, UART переключается на 107000. Это не исправляется автоматически; CLI сообщает об этой особенности при выборе режима.

Подтверждение принимается на прежней скорости. Отдельной паузы после настройки UART в исходном пути нет. При возврате команда 9600 отправляется на текущей повышенной скорости; после подтверждения и паузы переключается UART и очищаются буферы.

## Ошибки и состояние соединения

Переключение разрешено после успешной идентификации MS43. Явный отказ `B0` сохраняет прежнюю согласованную скорость, локальная настройка UART не выполняется. Потерянное или повреждённое подтверждение, неизвестный статус и ошибка локального переключения после `A0` оставляют скорость неопределённой.

В неопределённом состоянии `Session::baud_rate()` возвращает `None`, идентификация и дальнейшие переключения блокируются. Автоматического перебора скоростей или слепого повтора команды нет. Требуется восстановить соединение, приведя ECU и адаптер к исходным 9600; простое закрытие локального порта не гарантирует возврат скорости ECU. Такая блокировка — наше дополнение к исследованному поведению.

Закрытие или удаление сессии не отправляет скрытые команды. Пользователь библиотеки должен явно вызвать восстановление после операции; CLI делает это сам. Если одновременно произошли ошибка операции и ошибка восстановления, CLI сообщает обе.

## Основания и проверка

Исходные листинги находятся в `~/git/kek/ms4x/analysis/evidence/`:

- `communication.il.txt`, `0x060000cb` и `0x060000cc` — таблица скоростей и default 9600.
- `communication.il.txt`, `0x060000d9` и `0x06000008` — подготовка, подтверждение, пауза и переключение UART.
- `ui.il.txt`, `0x060001ce`, поле `0x04000148` — задержка 200 мс, передаваемая через фабрику и конструкторы MS43.
- `communication.il.txt`, `0x060000e5`; `ui.il.txt`, `0x06000135` и `0x06000129` — восстановление 9600 после операции, включая ошибку.

Добавлены две основные необходимые проверки: правильные команды разгона и возврата с соблюдением порядка и паузы; повреждённое подтверждение без переключения UART и с блокировкой последующих команд. Остальные существующие проверки сохранены. Новые зависимости, потоки и async runtime не добавлялись.

Аппаратная работа перечисленных скоростей пока не подтверждена. Нестандартные baudrate зависят от возможностей драйвера, кабеля и ECU; успешные сценарные тесты их совместимость не доказывают.
