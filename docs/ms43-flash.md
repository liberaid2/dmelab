# Чтение и запись прошивки MS43

## Команды и режимы

```sh
dmelab read --mode full --output full.bin
dmelab read --mode partial --output calibration.bin
dmelab write --mode full --input full.bin
dmelab write --mode partial --input calibration.bin
```

Режим по умолчанию — `full`. `--port` задаётся явно либо выбирается автоматически из единственного usbserial-адаптера. `--baud-rate` по умолчанию 125000; доступны также 19200, 38400, 50000 и исследовательский режим 107000. Чтение и запись на 9600 отклоняются: исходные 9600 используются для подключения и предварительных проверок, затем согласуется разгон.

После передачи библиотека пытается согласованно вернуть 9600. Ошибки операции и восстановления сохраняются вместе. `--timeout-ms` относится к идентификации и согласованию скорости; flash-транзакции используют исходные 1 с, стирание — 60 с. На блок чтения предусмотрено до 5 попыток, на программирование — до 10, с задержкой 200 мс между неудачными попытками.

## Чтение

| Режим | Размер файла | Источники ECU и смещения файла |
| --- | ---: | --- |
| Full | 512 KiB | Boot: `0x000000 → 0x00000`, `0xE000` байт; program: `0x090000 → 0x10000`, `0x60000`; calibration: `0x070000 → 0x70000`, `0x10000` |
| Partial | 64 KiB | Calibration: `0x070000 → 0`, `0x10000` байт |

В полном образе диапазон `0x0E000..0x10000` заполняется `FF` без чтения ECU. Чтение идёт блоками до 123 байт, с проверкой длины, XOR и статуса каждого ответа. Bootloader читается в составе полного образа; запрет изменения bootloader относится к стиранию и записи.

CLI резервирует новый выходной файл до открытия адаптера. Существующий файл не перезаписывается. Данные сохраняются после завершения обмена и возврата скорости; при ошибке созданный файл удаляется. Если удалить его не удалось, CLI сообщает путь незавершённого файла. Ошибка возврата скорости также считается ошибкой операции, даже если все байты были прочитаны.

## Подготовка записи

Полная запись принимает только 512 KiB; частичная — 64 KiB или calibration из 512 KiB. Проверяются размер и сигнатура MS43 `111430`. Перед подключением CLI проверяет входной образ; библиотека повторяет проверку для своих вызывающих сторон.

До разблокировки и стирания библиотека:

1. Идентифицирует MS43 на 9600.
2. Для partial сравнивает шестибайтовую версию firmware образа и ECU.
3. Читает напряжение запросом `0B 03`: байт полного ответа `[25] × 0.10196078 В`; отклоняет значения ниже 11,5 В, как исходная программа.
4. Для образа 64 KiB получает 40 байт контекста monitor checksum из ECU `0x0EFDB8`.
5. Исправляет CRC16 и monitor checksums в копии образа, проверяя границы таблиц и диапазонов.
6. Согласует выбранную повышенную скорость.

Входной файл остаётся неизменным. Для полного образа коррекция идёт в исходном порядке: boot CRC, program monitor, program CRC, calibration monitor, calibration CRC. Изменение boot CRC в памяти не приводит к записи bootloader. Для 64 KiB обязательны calibration monitor с контекстом и calibration CRC. Обхода предварительных проверок и checksum correction нет.

## Запись и финализация

Full Write: unlock → prepare program → erase/write program → finalize program без дополнительной проверки байта 8 → erase/write calibration → finalize calibration с проверкой. Partial Write выполняет prepare/erase/write/finalize только для calibration.

| Секция | Адрес ECU | Смещение полного образа | Передаваемый диапазон, байт |
| --- | --- | --- | ---: |
| Program, только Full | `0x090000` | `0x10000` | `0x5FFF0` |
| Calibration | `0x070000` | `0x70000` или `0` для 64 KiB | `0xFFEF` |

Блок записи — до 118 байт. Пары `FF FF` пропускаются после стирания, хвосты таких пар обрезаются по исходному алгоритму. Последние 16 байт program и 17 байт calibration не передаются; это не обещание сохранить их прежнее содержимое после стирания. Команды стирания и подготовки/финализации разрешены только для двух адресов из таблицы. Bootloader и пропуск образа никогда не стираются и не записываются.

Для unlock используется допустимый исходный параметр `r = 1` и восстановленный seed/key алгоритм. Ответ `A1` при финализации вызывает повторный опрос; наше ожидание ограничено 60 с вместо неограниченного исходного цикла. Подтверждения ECU проверяются, но отдельного полного побайтового readback после записи нет, как и в исследованных методах.

После успешной записи CLI выводит исходную инструкцию: выключить зажигание, подождать 10 секунд, вернуть ключ в положение 2. Сбой после стирания может оставить незавершённую секцию; восстановление повреждённого bootloader не поддерживается.

## Проверка и основания

Реализация основана на `~/git/kek/ms4x/MS43.md`, Python-портах `ms43_checksums.py` и `ms43_flash.py`, а также исходных IL: `communication 0x06000016..0x0600001e`, `0x060000df..0x060000e2`; `binary 0x06000022..0x0600002f`; предварительные проверки `ui 0x060001aa..0x060001ae`.

Три новые необходимые проверки покрывают контрольные суммы по независимым Python/CIL-векторам и публичные сценарии полного/частичного чтения и записи. Проверяются переданные исправленные данные, границы секций, отсутствие записи bootloader, разгон и возврат скорости. Эти автономные проверки используют сценарный транспорт.

По сообщению владельца проекта, чтение и запись прошивки проверены через Android-приложение на настоящем ЭБУ. Это аппаратная проверка общего Rust-кода через приложение; отдельные испытания CLI и восстановления после обрыва здесь не описаны.
