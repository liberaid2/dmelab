# Идентификация MS43

## Реализованный путь

`dmelab identify --port PATH` открывает serial-порт через `dmelab-transport-serial`, передаёт его в `dmelab-ms43::Session` и вызывает `identify()`. `dmelab-core::Transport` задаёт интерфейс блокирующего обмена. Реализация не создаёт потоки и не использует async runtime.

Начальные настройки FTDI K-line: 9600 бод, 8 бит данных, even parity, один stop bit, без flow control, RTS/DTR выключены. Наличие FTDI-чипа не заменяет K-line трансивер. Порт задаётся через `--port` либо выбирается автоматически, если на macOS найден ровно один `usbserial`-адаптер. Парные имена `cu`/`tty` учитываются как одно устройство с предпочтением `cu`. При отсутствии или неоднозначности выбора CLI завершается до открытия порта и просит указать путь. USB VID/PID используются только как информация в `dmelab ports`.

Опция `--baud-rate` включает [согласованную смену скорости](ms43-baud-rate.md): после начального распознавания на 9600 CLI переключается на выбранную скорость, повторно идентифицирует ЭБУ и возвращает 9600 перед выходом.

## Последовательность запросов

Все запросы адресованы `0x12`. Пакет содержит адрес, полную длину, payload и XOR предыдущих байтов. После отправки сначала принимается точное echo запроса, затем ответ ECU. Проверяются адрес, длина, XOR и положительный статус `0xA0`.

| Шаг | Payload | Результат |
| --- | --- | --- |
| Служебные данные | `0D` | В полном ответе байты `[57..60)` задают 24-битный адрес hardware ID |
| Hardware ID | `06 00 pp pp pp 08` | Восемь ASCII-байтов по адресу из ответа |
| Сигнатура flash | `06 00 0E FF CC 08` | Восемь ASCII-байтов из `0x0EFFCC` |
| Версия firmware | `06 00 0E FF BA 06` | Шесть ASCII-байтов из `0x0EFFBA` |

После служебного ответа выдерживается пауза 100 мс в вызывающем потоке. Это ожидание не создаёт новый поток. Первые шесть символов hardware ID должны быть `111430`; иначе идентификация останавливается до фиксированных чтений MS43. Сигнатура flash возвращается отдельно как `flash_identifier`, без утверждения, что это независимый аппаратный ID или версия firmware.

Буферы очищаются перед служебным запросом и перед каждым фиксированным чтением flash. Во время транзакции буферы не очищаются. Частичные чтения и записи собираются последовательно; бюджет времени общий для отправки, echo и ответа в каждой транзакции. Автоматических повторов нет. Порт освобождается при завершении CLI или удалении сессии.

Сам метод `Session::identify()` не выполняет разблокировку, стирание, запись, очистку ошибок или смену скорости. Он работает на текущей согласованной скорости. Смена скорости — отдельная операция `Session::change_baud_rate()`, которую CLI вызывает при выборе `--baud-rate`. VIN на этом этапе не читается. Ошибки протокола типизированы; CLI добавляет контекст операции и пути устройства.

## Основания реализации

Исследовательская база — `~/git/kek/ms4x/analysis/evidence/`. Ссылки на методы относятся к конкретной разобранной сборке MS4x Flasher 1.6.0:

- `communication.il.txt`, `0x06000021` — служебный запрос, указатель hardware ID, пауза и чтение восьми байтов.
- `communication.il.txt`, `0x060000c3` и `contracts.il.txt`, `0x0600010b` — выбор MS43 по сигнатуре `111430`.
- `communication.il.txt`, `0x060000d3`, `0x060000d4`, `0x060000e6` — фиксированные адреса и подготовка чтений.
- `communication.il.txt`, `0x0600000b`–`0x0600000e` — построение и проверка пакетов.
- `platform.il.txt`, `0x06000005` — отправка и проверка echo.
- `contracts.il.txt`, `0x060000df` — исходные настройки serial.

Исходные некорректные условия, принимавшие ответ при верном статусе ИЛИ достаточной длине, не воспроизводятся: статус и границы проверяются независимо.

## Проверки и аппаратный статус

Минимальные необходимые тесты проверяют полный сценарий из четырёх точных запросов с echo и частичными чтениями, остановку при неверном XOR и ненулевое завершение настоящего CLI при ошибке открытия устройства. Сценарные ответы синтетические; они не подтверждают тайминги или поведение реального ECU.

Подключённый FTDI во время реализации не обнаружен. Аппаратная идентификация остаётся непроверенной. Псевдотерминал macOS не поддерживает `IOSSIOSPEED` и управление modem lines, необходимые текущему serial-пути; аппаратный e2e не подменяется успешным тестом на PTY.

Для проверки на оборудовании подключите FTDI K-line и MS43, выполните `ports`, затем `identify` с явным путём. Сохраните результат, версию ОС, модель кабеля и логи `-v`; при ошибке проверьте, на каком этапе оборвался обмен. Успех идентификации не подтверждает возможность чтения или записи прошивки.
