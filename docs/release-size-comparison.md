# Размер release-сборок

## Принятое решение

Используем `opt-level = "z"`, `lto = "fat"`, `codegen-units = 1` и
`panic = "unwind"`. Профиль задан в корневом `Cargo.toml`; код и зависимости
продукта ради уменьшения размера не менялись. Полный LTO с `z` дал наименьший
CLI, а размер библиотек практически совпал с ThinLTO и `z`.

CLI собирается с `strip = "symbols"`. Для FFI сохраняем таблицу символов:
Android-скрипт генерирует Kotlin, затем удаляет ненужные символы только из
копий `.so` в `dist/android/`. Удаление символов до генерации проверено:
UniFFI завершает работу с `No UniFFI metadata found`.

`panic = "abort"` не применяем: UniFFI использует перехват паник. Сохранение
`unwind` оставляет прежнее поведение обработки ошибок.

## Сравнение вариантов

Измерено 3 ноября 2026 года: macOS ARM64, Rust 1.95.0, UniFFI 0.32.2,
NDK 28.2.13676358, Android API 23. Все варианты собраны из одних исходников,
без feature `bindgen` в поставляемой библиотеке. APK/AAB не собирались.

Размеры в **KiB (1024 байта)**. Кроме первой строки, показаны файлы после
strip. Для вариантов LTO использована одна единица генерации кода;
исходный release использовал 16.

| Вариант | CLI macOS | FFI macOS | ARM64 | ARMv7 | x86_64 | x86 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Исходный release, без strip | 1444,0 | 684,7 | 877,1 | 615,6 | 818,6 | 832,5 |
| Только strip | 1139,8 | 516,0 | 560,5 | 378,9 | 595,1 | 628,3 |
| ThinLTO, `3` | 984,3 | 483,4 | 526,0 | 361,9 | 564,6 | 587,3 |
| ThinLTO, `s` | 940,6 | 483,6 | 522,7 | 353,9 | 557,2 | 576,8 |
| ThinLTO, `z` | 845,5 | 452,0 | 511,6 | 343,7 | 556,4 | 567,3 |
| Полный LTO, `s` | 768,2 | 483,6 | 522,7 | 353,9 | 557,2 | 576,8 |
| **Полный LTO, `z`** | **672,8** | **452,0** | **511,6** | **343,7** | **556,4** | **567,3** |

Для macOS dylib в эксперименте применялся `strip -x` к отдельной копии.
Обычный `cargo build --release --workspace` сохраняет её символы для
инструментов: текущая `target/release/libdmelab_ffi.dylib` занимает 660,5 KiB.
CLI и Android-скрипт уже автоматически выдают уменьшенные артефакты.
В сравнении с исходным release CLI уменьшился на 53%, Android `.so` — на 32–44%.

## Выполненные проверки

- Для каждого из шести профилей прошли все 13 Rust-тестов в release:
  протокол, идентификация, смена скорости, DTC, live data, контрольные суммы,
  чтение/запись flash и исключение bootloader из записи.
- Выполнены 24 запуска Kotlin → UniFFI → Rust → транспорт Kotlin после strip:
  идентификация, чтение DTC, live data и очистка DTC, включая ошибки и повторный вход.
- Kotlin API совпал для всех профилей и четырёх ABI; host- и Android-bindings
  скомпилированы без Gradle. Все 119 экспортируемых символов библиотек сохранены.
- Вывод справки CLI и ошибки отсутствующего порта совпал между профилями.
  После применения настроек повторно собраны workspace и четыре Android ABI,
  выполнены release-тесты.

Это автономные проверки; Android-библиотеки на устройстве и обмен с ECU
здесь не запускались. Скорость работы с реальным ECU не измерялась.
Локальные артефакты, журналы, команды и численные результаты сохранены в
`dist/size-comparison/`; этот каталог исключён из контроля версий.

## Повторная сборка

```sh
cargo build --release --locked --workspace
# Выбрать установленный toolchain с Android targets, если требуется:
RUSTUP_TOOLCHAIN=stable bash scripts/build-android.sh arm64-v8a armeabi-v7a x86_64 x86
```

При самостоятельном сравнении меняйте настройки через
`CARGO_PROFILE_RELEASE_OPT_LEVEL`, `CARGO_PROFILE_RELEASE_LTO` и
`CARGO_PROFILE_RELEASE_CODEGEN_UNITS`, используйте отдельный `CARGO_TARGET_DIR`.
Сравнивайте артефакты с одинаковой обработкой strip; не удаляйте таблицу
символов FFI до генерации bindings.
