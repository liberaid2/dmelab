# Стек Rust и CLI

## Область решения

Первый этап — Rust-библиотека и CLI с FTDI K-line. Используем Rust stable, edition 2024 и Cargo workspace. Конкретную версию toolchain фиксируем в `rust-toolchain.toml` при создании workspace, зависимости — в манифестах и `Cargo.lock`.

## Выбранные компоненты

| Компонент | Решение | Где используется |
| --- | --- | --- |
| Базовые типы и ввод-вывод | `std` | Библиотека и CLI |
| Последовательный порт | `serialport` | `dmelab-transport-serial` |
| Типизированные ошибки | `thiserror` | Библиотечные крейты |
| Контекст и объединение ошибок | `anyhow` | Только `dmelab-cli` |
| Аргументы и подкоманды | `clap` | `dmelab-cli` |
| Диагностические события | `tracing` | Библиотека и CLI |
| Вывод логов | `tracing-subscriber` с синхронным выводом | Настраивает CLI |
| Kotlin bindings | UniFFI 0.32.2, без default features | `dmelab-ffi`; генератор включается feature `bindgen` |
| Android `.so` | `cargo-ndk`, Android NDK, API 23+ | `scripts/build-android.sh`, без Gradle |
| Desktop FFI | Feature `desktop`, существующий serial-транспорт, Kotlin/JVM + JNA JAR | `scripts/build-desktop.sh`; первая цель macOS ARM |
| Сборки CLI | Apple SDK для macOS; Zig 0.16.0 и cargo-zigbuild 0.22.3 для Linux musl и Windows GNU LLVM; Python 3 для архивов | `scripts/build-cli.sh`, четыре платформы; только инструменты сборки |
| Проверки | Стандартные Rust-тесты, rustfmt, Clippy | Workspace |

Зависимости добавляем при реализации соответствующей функции. `serde` и `serde_json` подключаем при появлении машинного вывода; сейчас они не нужны ядру. UniFFI изолирована в `dmelab-ffi` и не требуется для сборки CLI. Генератор и его транзитивные зависимости не входят в Android-сборку без feature `bindgen`. Транзитивный `anyhow` в инструментах UniFFI не используется в API библиотек dmelab.

## Выполнение без потоков и Tokio

Все операции синхронные и блокируют вызывающий поток до завершения. CLI вызывает библиотеку в основном потоке. Библиотека не создаёт рабочие потоки, очереди исполнителей и фоновые задачи. Одна сессия обрабатывает одну операцию за раз.

Запрещены создание потоков через `std::thread`, пулы потоков, Tokio, другие async runtimes и собственные `async` API. Не используем Rayon и фоновые обработчики логов. При добавлении зависимости проверяем, не создаёт ли выбранная конфигурация скрытые рабочие потоки. Использование драйвером ОС собственных механизмов выполнения находится за границей этого ограничения.

Библиотека может вызываться из потока, которым управляет внешнее приложение. Выбор этого потока принадлежит вызывающей стороне; Rust-код не переносит работу автоматически. Этот контракт сохраняется для будущей UniFFI-обёртки.

Чтения ограничиваем конечными таймаутами. Прогресс вызывается синхронно и не должен задерживать обмен или повторно запускать операцию на той же сессии. Отмену проверяем в безопасных точках протокола; она не означает немедленного закрытия соединения во время записи. Будущий сигнал отмены от приложения не должен требовать захвата занятой сессии.

Ограничение относится к коду продукта и собственным тестам, а не к внутренним потокам компилятора или стандартного тестового раннера.

## Границы ошибок

Публичные операции библиотеки возвращают `Result<T, Error>` с предметными вариантами: таймаут, некорректный пакет, неподдерживаемая операция и другие подтверждённые случаи. `thiserror` помогает реализовать стандартный интерфейс ошибок. Исходную причину сохраняем, когда она полезна вызывающей стороне.

CLI использует `anyhow::Result` и добавляет контекст пути, команды или операции. Различать ошибки и решать, допустим ли повтор, нужно до преобразования в итоговый отчёт CLI. В библиотечных крейтах `anyhow` не используем.

## Кроссплатформенный serial

`serialport` предоставляет общий блокирующий API для macOS, Linux и Windows. Отдельную библиотеку для каждой ОС не выбираем. Собственный адаптер скрывает типы `serialport` за контрактом транспорта; ядро и реализации DME не зависят от платформенных serial API.

Первая целевая проверка — macOS и реальный FTDI K-line кабель. Нестандартные скорости, parity, echo и задержки подтверждаем на конкретном оборудовании. Поддержка ОС зависимостью не является подтверждением аппаратной совместимости dmelab на этой ОС.
