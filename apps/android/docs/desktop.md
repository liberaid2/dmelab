# Приложение macOS

Desktop-приложение использует общий Compose UI и исполнитель сценариев из
`:shared`; `:ecu` подключает отдельные JVM bindings UniFFI и native serial.
Android сохраняет собственные приложение, транспорт и системные адаптеры.

## Подготовка и запуск

Текущая платформа — macOS Apple Silicon с ARM JDK 21; для сборки подходит
JBR 21 из Android Studio. Архитектура JVM должна совпадать с native-библиотекой.
Отдельно установленная Java не требуется пользователю собранного `.app`:
Compose Desktop упаковывает сокращённый runtime вместе с приложением.

Сначала подготовьте UniFFI из корня общего репозитория:

```sh
bash scripts/build-desktop.sh aarch64-apple-darwin
```

Контракт артефактов — [desktop bindings](../../../docs/desktop-bindings.md).
Модуль `:ecu` использует `../../dist/desktop/kotlin` и
`../../dist/desktop/resources`, включая `darwin-aarch64/libdmelab_ffi.dylib`.
Bindings и библиотека должны происходить из одной сборки; сгенерированный
Kotlin вручную не редактируется. Android-генерация подключается отдельно.

Из `apps/android`:

```sh
./gradlew :desktopApp:run
./gradlew :desktopApp:createDistributable
./gradlew :desktopApp:packageDmg
```

Если Gradle запущен на JBR из Android Studio без `jpackage`, передайте полный JDK 21
через `-PdesktopJavaHome=/absolute/path/to/jdk`. JVM Gradle при этом менять не нужно.

Первая команда запускает приложение из исходников, вторая собирает `.app`
с runtime, третья — установочный DMG. Результаты:

- `desktopApp/build/compose/binaries/main/app/DME Lab.app`;
- `desktopApp/build/compose/binaries/main/dmg/` — DMG с именем и версией пакета.

Подпись Developer ID и notarization пока не настроены. Текущая упаковка
предназначена для локальной разработки; поставка подписанного приложения
потребует отдельной настройки сертификатов и notarization.

## Подключение и операции

Подключите FTDI K-line кабель к Mac и OBD, выберите serial-порт на экране
подключения и явно запустите идентификацию. Предпочтительны macOS-порты
`/dev/cu.*`; наличие порта само по себе не подтверждает связь с ЭБУ.
Разрешение Android USB здесь не используется.

Сценарии, подтверждения записи и сброса DTC, правила одной операции и обработка
ошибок остаются общими. Выбор BIN и места сохранения выполняется нативными
файловыми диалогами macOS. Существующий файл заменяется после подтверждения
в диалоге и успешной полной записи временного файла. Ошибка или отмена до
фиксации сохраняет прежний файл. Размер и формат BIN проверяет библиотека;
импорт ограничен 512 КиБ, запись повторно проверяет SHA-256.

Работой владеет scope приложения; закрытие экрана не отменяет обмен.
При закрытии окна или выходе во время операции показывается подтверждение:
непрерывный Live Data можно остановить и дождаться завершения, для flash
необходимо дождаться возврата операции. Принудительное завершение процесса
не является безопасной отменой.

На время Live Data, чтения и записи прошивки процесс `/usr/bin/caffeinate` удерживает систему от
автоматического сна. Он освобождается после остановки, ошибки или отмены;
завершение JVM также снимает assertion. Экран может выключаться.

## Файлы и восстановление

Данные находятся в `~/Library/Application Support/DME Lab/`:

- `live_data_logs/` — постоянные CSV; автоматического удаления нет;
- `cache/live_data_exports/` — ZIP для экспорта;
- `cache/firmware_imports/` — проверенные копии входящих BIN;
- `operation-running` — технический маркер незавершённого обмена.

Имена CSV используют местную дату и время устройства, например
`ms43_live_2026-11-10_19-30-00.csv`; совпадения получают `-1`, `-2` и далее.
Доступны переименование, множественный выбор и экспорт всех готовых логов в ZIP.
Формат, выбранные группы и восстановление незавершённой строки описаны
в [документе CSV](live-data-csv.md). Активный `.csv.part` нельзя экспортировать;
после аварийного завершения он восстанавливается как `_partial.csv`.

Кеш ZIP и импортов очищается при следующей подготовке соответствующих файлов
после 24 часов. Завершённые CSV сохраняются до явного удаления пользователем.
Удаление `.app` само по себе не удаляет каталог Application Support.

Действие показа файлов открывает их в Finder. Это не встроенный native Share
sheet: отправить выделенные CSV или ZIP можно из меню «Поделиться» Finder,
либо сохранить копию через диалог экспорта.

Перед обменом исполнитель атомарно сохраняет маркер операции. После перезапуска
незавершённая операция показывается с неизвестным результатом; команды ЭБУ
и запись автоматически не повторяются. Каталог логов восстанавливается из файлов.

## Проверки

Сборка и запуск без кабеля подтверждают загрузку native-библиотеки и UI,
но не обмен с реальным ЭБУ. После desktop-изменений сохраняются Android-сборка,
Lint и существующие JVM-проверки из [инструкции сборки](build.md).
Фриз на новые тесты действует и здесь; аппаратную проверку указываем отдельно.
