# Токены дизайна

## Визуальная основа

dmelab использует фиксированную тёмную тему: графитовый фон, разделение
поверхностей по яркости, фиолетовый акцент и дополнительный мятный
из палитры иконки. Цвета статусов сохраняют привычный смысл.
Системная тема и цвета обоев не меняют палитру. Системные панели имеют светлые
иконки; фон окна запуска также тёмный.

Токены находятся в `shared/src/commonMain/kotlin/.../common/ui/theme/` внутри `:shared`. Общие кнопки, карточки
и другие UI-компоненты не вводим: экраны используют обычные Compose/Material 3
компоненты и значения темы.

## Цвета

Иконка лаунчера использует утверждённый пользователем пиксельный OBD-рисунок
в фиолетово-мятной палитре. Готовые PNG находятся в `app/src/main/res/mipmap-*`,
адаптивная иконка — в [ic_launcher.xml](../app/src/main/res/mipmap-anydpi/ic_launcher.xml),
её слои — в `app/src/main/res/drawable/`.
Цвет её фона задаётся ресурсом `dme_icon_background`.

Источник палитры — `DmeColors` в `Color.kt`. Основные роли подключены к
`MaterialTheme.colorScheme` через `DMELabTheme`.

| Роль | Значение | Назначение |
| --- | --- | --- |
| background | `#0B1018` | Фон экрана |
| surfaceLow | `#0E1621` | Нижний уровень поверхностей |
| surface | `#121A26` | Обычная карточка |
| surfaceRaised | `#1A2636` | Панель действий, иллюстрация |
| surfaceHigh | `#223247` | Бейджи и недоступные действия |
| outline / outlineStrong | `#29384B` / `#405775` | Границы и детали |
| textPrimary | `#F0F4FA` | Основной текст |
| textSecondary | `#B1BED0` | Описание и подписи |
| textMuted | `#8C9CB2` | Второстепенный и недоступный текст |
| accent / onAccent | `#C46AF0` / `#291535` | Основное действие и его текст |
| accentContainer / onAccentContainer | `#302039` / `#F2DDFB` | Подложка выбранного состояния и её текст |
| accentOutline | `#74488A` | Граница выбранного состояния |
| mint / onMint | `#94DEB4` / `#10291F` | Дополнительный акцент и его текст |
| mintContainer / onMintContainer | `#1B3029` / `#D4EBDD` | Мятная подложка и её текст |

Фиолетовый используется в `primary`: основные кнопки, ссылки, выбранные
контролы и индикаторы. Мятный — в `secondary` и статусе успешного завершения;
он не заменяет обозначение успеха текстом. `tertiary` остаётся нейтральным.
Яркие неоновые оттенки иконки не переносим напрямую на большие поверхности.
Фон, карточки, границы и обычный текст остаются графитовыми и серыми;
предупреждения — янтарными, ошибки — красными. Кремовый из иконки не вводим
как третий акцент, чтобы интерфейс оставался сдержанным.
Синий не используем для действий и выбранных состояний. Существующие
синевато-графитовые фоны, поверхности и нейтральные границы сохраняются.
Кабель и детали ЭБУ на иллюстрации подключения используют мятный `secondary`.

`info`, `success`, `warning`, `error` содержат три согласованных значения:
`content`, `container`, `outline`. Для статусов используем эту тройку целиком,
не вычисляем фон через произвольную прозрачность текста. Значение статуса
обязательно объясняется подписью, а не только цветом.

Информационный статус: `#C46AF0` / `#251A2C` / `#61406D`;
успех: `#94DEB4` / `#162C22` / `#365844`
(`content` / `container` / `outline`). Контраст основной кнопки с её текстом —
5,3:1; фиолетового текста на основном фоне — 6,0:1; мятной кнопки с её
текстом — 9,8:1. Сохраняем фиксированную тёмную тему без dynamic color.

В feature-коде не задаём hex-цвета. Для обычного UI берём роли MaterialTheme,
для статусов и дополнительных оттенков — DmeColors. `dme_background` в Android
XML зеркалит фон для окна запуска; при изменении background обновляем оба места.
`dme_accent` зеркалит `DmeColors.accent` для `android:colorAccent`, активных
нативных контролов и ссылок; при изменении акцента синхронно обновляем оба места.
В Compose кнопки, переключатели, ссылки и выделение текста получают цвет
из общей MaterialTheme, без локальных переопределений.

## Типографика

`DmeTypography.material` задаёт роли `MaterialTheme.typography`. Используется
системный Sans Serif; все размеры в sp, высоты контейнеров допускают рост текста.

| Роль | Размер / интерлиньяж | Начертание |
| --- | --- | --- |
| headlineLarge / Medium / Small | 32/40, 28/36, 24/32 | Bold, SemiBold, SemiBold |
| titleLarge / Medium / Small | 22/28, 18/24, 16/24 | SemiBold |
| bodyLarge / Medium / Small | 16/24, 14/22, 12/18 | Normal |
| labelLarge / Medium / Small | 14/20, 12/16, 11/16 | SemiBold, Medium, Medium |

Дополнительные роли: `brand` — 18/24 ExtraBold с межбуквенным интервалом 1 sp;
`identifier` — 16/24 Medium Monospace для hardware ID и версий прошивки.
Не переопределяем fontSize/fontWeight на экране ради отдельного заголовка.

## Отступы и размеры

`DmeSpacing`: `xxs=4`, `xs=8`, `sm=12`, `md=16`, `lg=24`, `xl=32`, `xxl=48` dp.
Базовый ритм — 4 dp. Поля экрана и расстояния между секциями — lg;
отступы карточки — md или lg; расстояния внутри группы — xs или sm.

`DmeSizing`: минимальная область касания — 48 dp, минимальная высота основной
кнопки — 56 dp, маркер шага — 32 dp, иконка/индикатор загрузки — 20 dp,
точка статуса — 8 dp, граница — 1 dp, штрих индикатора — 2 dp.
`featureArtwork=80` dp — контейнер векторной иллюстрации подготовительного
состояния сценария; размеры иллюстрации онбординга определяются её геометрией.
Для кнопок задаём минимальную высоту, чтобы крупный шрифт не обрезался.

## Скругления

`DmeShapes` подключены к `MaterialTheme.shapes`: extraSmall=8, small=12,
medium=16, large=24, extraLarge=32 dp. Medium используется для кнопок,
выбора адаптера и сообщений; large — для больших карточек и иллюстраций.
Для круглых маркеров и бейджей используем стандартный `CircleShape`.

Геометрия конкретного рисунка и его размер остаются рядом с рисунком.
Не превращаем каждую координату Canvas в общий токен.

## Применение

```kotlin
Modifier.padding(horizontal = DmeSpacing.lg, vertical = DmeSpacing.md)
Modifier.heightIn(min = DmeSizing.buttonHeight)
MaterialTheme.colorScheme.surface
MaterialTheme.shapes.medium
MaterialTheme.typography.titleSmall
DmeTypography.identifier
DmeColors.warning.container
```

Новое значение добавляем в общую шкалу только при повторяемом назначении.
Токены не управляют доступностью операций, состоянием сессии и бизнес-логикой.
